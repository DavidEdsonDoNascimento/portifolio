# Portfolio Web — Dark Tech Premium

Bilingual (EN / PT-BR) personal portfolio of a Senior Full Stack Software Engineer, with a small interactive
mini game (*Packet Rush*). Next.js standalone build, ready for Docker/Coolify.

## Stack

- Next.js 16 (App Router) · React 19 · TypeScript (strict)
- Tailwind CSS 4 (design tokens in `src/app/globals.css`)
- next-intl (EN / PT-BR) · Lucide React (icons) · ESLint
- Fonts via `next/font`: Space Grotesk (headings), Inter (body), JetBrains Mono (tech details)

## Requirements

- Node.js 22.18+ (Docker image uses Node 24)
- pnpm 11.18.0 (pinned via `packageManager`; run `corepack enable` to get it)

## Getting started

```bash
pnpm install
pnpm dev        # http://localhost:3000
```

| Script              | Purpose                                                      |
| ------------------- | ------------------------------------------------------------ |
| `pnpm dev`          | Development server                                           |
| `pnpm build`        | Production build (standalone)                                |
| `pnpm start`        | Run the production build                                     |
| `pnpm lint`         | ESLint                                                       |
| `pnpm typecheck`    | Route types + `tsc --noEmit`                                 |
| `pnpm test`         | Game rules, translations, URL/SEO helpers (`node --test`)    |
| `pnpm resume:build` | Regenerate the public resume PDFs (needs a local Chrome)     |

## Internationalization

English is the default language (`/`); Brazilian Portuguese lives at `/pt`. There is no browser-language
detection and no cookie: the URL is the source of truth. `/api/health` is not prefixed.

- Copy lives in `messages/en.json` and `messages/pt.json` (same keys; `pnpm test` fails if they diverge).
- Structural data (ids, URLs, companies, technologies, dates) stays in `src/data/` and is shared; texts are
  looked up by id (e.g. `projects.items.<id>.title`).
- Routing: `src/i18n/routing.ts` and `src/proxy.ts` (Next 16 replacement for `middleware.ts`).

## SEO and production readiness

Everything public-facing depends on one variable, read **at build time** (Next.js inlines it):

```bash
NEXT_PUBLIC_SITE_URL=https://yourdomain.com
```

`src/lib/site-url.ts` accepts only an absolute **HTTPS origin of a public domain** (no credentials, query,
fragment, path or port; no `localhost`/IPs) and normalizes it. Anything else is ignored with a build warning.

| | Without a valid `NEXT_PUBLIC_SITE_URL` (default, safe for dev) | With it |
| --- | --- | --- |
| `<meta name="robots">` | `noindex, nofollow` | `index, follow` |
| canonical / hreflang | not emitted | `/` (en), `/pt` (pt-BR), `x-default` → `/` |
| Open Graph / Twitter image | not emitted | `/og/en.png`, `/og/pt.png` (1200×630, absolute URLs) |
| `/robots.txt` | `Disallow: /` | `Allow: /`, `Disallow: /api/`, absolute `Sitemap:` |
| `/sitemap.xml` | empty | `/` and `/pt` with hreflang alternates |

- Titles and descriptions come from `messages/*.json` (`metadata`). The Open Graph images are prerendered at
  build time by `src/lib/og-image.tsx` (`next/og`; fonts in `src/assets/fonts`, OFL).
- Icons: `src/app/icon.svg`, `favicon.ico`, `apple-icon.png`.
- The proxy matcher leaves `/api`, `/og/*.png`, icons, `robots.txt`, `sitemap.xml` and `/resume/*` alone.

### Public resume

`public/resume/` holds one PDF per language, generated by `pnpm resume:build` (set `CHROME_BIN` to override the
Chrome binary) from the **same data and messages as the site**, so they can only contain what is already
published here: no phone number, no private data. Chrome metadata (user agent, dates) is blanked afterwards.
Files in `private/` are git- and docker-ignored and are never read by the script.

## Docker

```bash
docker build -t portfolio-web .
# with a public domain (it must be present at build time):
docker build --build-arg NEXT_PUBLIC_SITE_URL=https://yourdomain.com -t portfolio-web .
docker run --rm -p 3000:3000 portfolio-web
curl http://localhost:3000/api/health   # {"status":"ok"}
```

The image is multi-stage (`pnpm install --frozen-lockfile` → build → minimal runtime, pnpm via Corepack), runs as
a non-root user, listens on port `3000` with `HOSTNAME=0.0.0.0`, and uses Next.js `output: "standalone"`.
`next/font/google` downloads fonts at build time, so the build needs outbound network access.

## Deploy (Coolify)

Setup: Git repository → Build Pack **Dockerfile** → internal port **3000**. No database, no persistent volumes.
Health endpoint: `GET /api/health`.

**Stage 05B checklist** (nothing below is configured yet):

1. Register the domain and point DNS at the VPS; decide apex vs `www` (one redirects to the other).
2. In Coolify set the application domain with `https://` (Let's Encrypt) and keep port `3000`.
3. Add `NEXT_PUBLIC_SITE_URL=https://yourdomain.com` as a **build-time variable** (the Dockerfile declares the
   matching `ARG`; without it the value never reaches `next build`). Use the exact public origin.
4. **Rebuild**, don't just restart: the value is baked into the static pages. Redo it whenever the domain changes.
5. Verify in production: `curl -s https://yourdomain.com | grep -E 'canonical|hreflang|og:image|robots'`, the same
   for `/pt`, plus `/robots.txt`, `/sitemap.xml`, `/og/en.png`, `/api/health` and both resume PDFs.
6. Submit `sitemap.xml` to Google Search Console and refresh the link preview cache (LinkedIn Post Inspector).

## Project structure

```
src/
  app/                 [locale]/ (layout, page), og/ (image routes), robots.ts, sitemap.ts,
                       api/health, icons, globals.css (tokens)
  components/
    layout/            Header (client: menu, language switcher), Footer
    sections/          Hero, Projects, Experience, InteractiveLab (Packet Rush), About, Contact
    ui/                ButtonLink, SectionHeading, Badge
  config/site.ts       name, nav, contact links, resume paths (language-independent)
  i18n/                routing, request config, navigation helpers (next-intl)
  lib/                 game rules, URL/SEO helpers, OG image, formatters (+ tests)
  data/                structural content (projects, experience, skills, education)
  assets/fonts/        OFL font subsets for the OG image and resume
messages/              en.json, pt.json
public/resume/         public resume PDFs (EN, PT)
scripts/               build-resume.mjs
ref/                   local reference only (see below)
```

## The `ref/` folder

`ref/Rival-pro/` holds the licensed BootstrapMade *Rival* template, used **only as a visual/structural reference**
during development. It is git-ignored, docker-ignored, excluded from lint/typecheck, and nothing from it is
shipped. The site recreates the relevant ideas in React + Tailwind without Bootstrap, jQuery plugins or PHP forms.
